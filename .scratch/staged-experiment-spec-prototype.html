Compact staged specification

One fixed task

  • Input: one bounded English financial passage, one supplied public company, and one supplied applicable aspect.
  • Limit the complete ModernBERT input to 1,024 tokens, including the passage, company, aspect, and special tokens. Use consecutive complete sentences. Reject an example when its target and required label evidence do not fit. Give the exact same bounded passage, company, and aspect to every human and model.
  • Output: positive, neutral, negative, or insufficient evidence. Invalid target or aspect pairs are rejected before scoring.
  • Stage 1 aspects: financial performance; demand and commercial traction; operations, supply, and capacity; outlook and expectations.
  • Apply the frozen target gate, aspect gate, narrowest-supported-aspect rule, speaker-neutral rule, no-material-effect rule, and conservative conflict rule.

Easy to game: Repeated prompt, threshold, candidate, seed, or checkpoint choices can use the development set until a good result appears. Proposed rule: predeclare one change budget and an append-only decision log. Seal the final selection procedure before blind data exists.
Unauditable candidate intake: The source, extraction, event grouping, deduplication, ordering, and replacement rules are not fully frozen. Proposed rule: seal a source-specific candidate manifest and deterministic sampling rule before labeling starts.
Ambiguous Stage 2 and Stage 3 training: Two sources enter each stage. The plan does not say if their data enters one joint checkpoint or in a fixed order. Proposed rule: add both new-source datasets together, train one cumulative checkpoint, and test that same checkpoint on all required sources.
Ambiguous GPT regression use: The plan does not say if an earlier source calls GPT again at each later stage. New calls add cost and a new failure point without changing the baseline design. Proposed rule: seal and reuse one valid GPT prediction file for each source. Run only the new specialist on earlier regression sets.
Infeasible invalid-run rule: One bad blind call requires a new untouched blind set, but the data plan and budget include only one blind set for each source. Proposed rule: permit no automatic rerun. Return to a new planning decision for added data, cost, and invalidation controls.
Unclear free-label schedule: The latest size includes development votes, so each route can process 21,000 examples. The Groq plan can need 93 daily token grants, not the earlier 88-day estimate for only 20,000 candidates. Proposed rule: use the later 21,000-example estimate and require a dated account-limit calculation.
Easy to game budget categories: A total-only spend check can hide a paid label call or an unapproved move between categories. Proposed rule: enforce each frozen category limit and the USD 100 total in one append-only ledger. Require a new map decision before a category limit changes.
Claim boundary: Balanced 400-example source sets test capability. They do not estimate real source or label prevalence. Proposed rule: limit every result to this balanced, company-only, four-aspect task.
